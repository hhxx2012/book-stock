📝 详细部署步骤

1

注册 Supabase 账号并创建项目

访问 https://supabase.com，使用 GitHub 或邮箱注册。

创建一个新项目，记住项目密码（数据库密码），选择离你最近的区域（如 Singapore 或 Tokyo）。

Supabase 免费版包含：500MB 数据库空间、无限 API 请求、2GB 带宽，完全满足本系统需求。
2

获取项目连接信息

进入项目后，点击左侧菜单 Project Settings → API，找到以下信息：

  • Project URL（如：https://xxxxxxxxxxxx.supabase.co）
  • anon public API Key（以 eyJ 开头的一长串字符）
请妥善保管 anon key，不要泄露给不信任的人。它决定了谁能访问你的数据库。
3

创建数据库表结构

点击左侧 SQL Editor → New query，把项目根目录下 supabase/migrations.sql 文件中的全部 SQL 复制粘贴进去，然后点击 Run。

这个 SQL 会创建以下数据表：

  • users - 用户表
  • roles - 角色定义表
  • role_permissions - 角色权限表
  • grades - 年级列表
  • subjects - 科目列表
  • difficulties - 难度列表
  • books - 书本信息表
  • stock - 库存表
  • forecasts - 预计/领取表
  • logs - 操作日志表
  • system_settings - 系统设置表
SQL 中已经预置了默认的年级、科目、难度数据和角色定义，执行后即可使用。
4

配置环境变量

在项目根目录创建 .env 文件（复制 .env.example），填入你的 Supabase 信息：

VITE_SUPABASE_URL=https://你的项目ID.supabase.co VITE_SUPABASE_ANON_KEY=你的anon-key
不要把 .env 文件提交到 Git！系统已经配置了 .gitignore，但请再确认一次。
5

本地测试在线模式

配置好环境变量后，在本地运行：

npm install npm run dev

打开浏览器访问 http://localhost:5173，此时系统会自动检测到 Supabase 配置，所有数据操作都会同步到云端数据库。

如果删除 .env 文件或清空两个变量，系统会自动回退到本地 localStorage 模式，方便测试。
6

部署到 Vercel（免费托管）

方式一：Git 部署（推荐）

  1. 将项目推送到 GitHub 仓库
  2. 访问 https://vercel.com，导入该仓库
  3. 在 Vercel 的 Environment Variables 中添加：VITE_SUPABASE_URL 和 VITE_SUPABASE_ANON_KEY
  4. 点击 Deploy，等待构建完成

方式二：手动部署

npm run build # 然后将 dist/ 文件夹内容上传到任何静态托管服务

🔐 权限与多用户说明

本系统采用角色权限制，Supabase 在线模式下仍然保留本地原有的权限体系：

  • 超级管理员：拥有所有权限，可管理用户、角色、系统设置
  • 管理员：可管理书本、库存、预计、领取
  • 教务员：可管理自己校区的库存和预计
  • 教师：可查看库存、提交预计/领取申请
当前版本使用基于角色的访问控制，所有用户共享同一套数据。后续如需接入微信登录，可在 Supabase Auth 中配置 OAuth Provider。

⚠️ 注意事项

  • Supabase 免费版数据库有 500MB 限制，对于书本管理系统来说足够使用数年
  • 如果不再使用在线模式，直接删除 .env 文件即可回退到本地模式，数据互不影响
  • 在线模式下，所有用户看到的数据是实时同步的，无需手动刷新
  • 建议定期在 Supabase Dashboard 中备份数据（Table Editor → 各表 → Export）
  • 如需限制数据库访问权限，可在 Supabase 的 Row Level Security (RLS) 中配置更细粒度的规则
